- Till hardware config is device-local (src/lib/hardware.ts, ESC/POS in escpos.ts); network printers need an HTTP print address. Why: browsers lack raw TCP.
- Receipt logos use private store-prefixed files in the existing image bucket; cache downloaded image data per staff/store for offline preview and raster printing. Why: public links and expired signed URLs must not expose shop assets or break offline receipts.
- Shared shop changes use one store-filtered realtime channel in useShopUpdates, coalescing updates across shared queries and credit snapshots; existing reconnect polling remains the fallback. Why: till and Back Office must share current records without exposing secrets or duplicating listeners.
- Checkout shares one client reference across online and offline retries; queue and receipt commit atomically, and local stock subtracts durable queued quantities. Why: lost responses and reloads must not double-sell or lose sales.
- Cashier dashboard reads filter by store, cashier and Harare day; combine cached cloud totals with queued sales deduplicated by client reference. Why: offline totals must remain personal and never double-count upload retries.
- Shift X/Z reports use scoped downloaded summaries and item lines plus device sales missing from server references; uploads atomically retain device history before removing queued sales. Why: disconnected reports must keep totals across upload/reload and never count a sale twice.
- Resolve membership before caching first-login profiles; explicit sign-out clears the separate active device session. PIN aliases use verified profile identities, and password/OAuth requires PIN verification before saving a hash. Why: offline access must survive refresh failures without guessing PINs or crossing cashier scopes.
- Daily settlement expectations are derived on read by src/lib/settlement.ts; `daily_settlements` stores only the manager's counted snapshot per Harare day. Why: settlement can never drift from till records.
- Offline credit: the till checks limits against a downloaded `customer_credit_snapshot` plus this device's account sales and queued debt payments not yet in it (src/lib/offline-credit.ts); uploads use `complete_offline_sale_v2` and idempotent `receive_offline_customer_payment`, which accept the sale because goods already left. Why: limits must hold with no internet without double-counting uploads.
- Day settlements saved offline queue on the device (src/lib/settlement-queue.ts) and upload after sales; settlement skips debt-payment drawer paid-ins already counted as repayments. Why: no double-counted cash.
- Daily settlements auto-settle nightly via pg_cron `auto_close_daily_settlements` (SQL mirror of src/lib/settlement.ts: lines, shift cash counts, `_owed` customer total, `auto=true`); a manager save sets `auto=false`. Keep both calculations in sync. Why: no day is left unsettled.
- Offline receipts use TXN numbers reserved from the shop sequence while online (src/lib/receipt-numbers.ts); client_ref `RSV-<n>-<uuid>` lets a BEFORE INSERT trigger on sales apply the reservation for that store and cashier. Why: offline and uploaded receipts must share one sequential number without collisions between tills.
- Self-serve trial stores are provisioned only by the public `signupStore` server function via service-role `create_trial_store` (settings, payment types, branch, starter catalog, 14-day clock); failed owner creation calls `discard_trial_store`. Why: signup must never touch the vendor store or leave half-made shops.
